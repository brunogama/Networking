# Phase 10.1: Apply DRY to NetworkingMacros Repeated Code - Research

**Researched:** 2026-02-15
**Domain:** Swift macro implementation refactoring and code deduplication
**Confidence:** HIGH

## Summary

Phase 10.1 targets systematic elimination of code duplication across 5 HTTP macro implementations (GET, POST, PUT, PATCH, DELETE) that share ~80% identical logic but exist as separate 300-374 line files. The core duplication involves argument extraction (path, headers, query parameters), syntax detection (old vs new), validation, and code generation pathways.

**Primary recommendation:** Extract shared logic into protocol-oriented helpers that leverage the existing MacroTemplateKit Declaration ADT, following the InterceptorCodeGenerator pattern already established in Phase 10.

**Key insight:** All HTTP macros follow identical 6-phase expansion workflow (validate → extract → detect syntax → validate params → generate → return), differing only in HTTP method string and body parameter requirement (POST/PUT/PATCH require body, GET/DELETE do not).

### Pattern 1: Protocol-Oriented Shared Logic
**What:** Define protocol for HTTP macro expansion with default implementations.
**When to use:** When multiple struct types share identical workflow with minimal variation.

**Example:**
```swift
// Sources/NetworkingMacros/HTTP/HTTPMacroBase.swift
import SwiftSyntax
import SwiftSyntaxMacros
import MacroTemplateKit

/// Configuration for HTTP method-specific behavior
struct HTTPMethodConfig: Sendable {
  let method: String              // "GET", "POST", etc.
  let requiresBody: Bool          // true for POST/PUT/PATCH
  let supportsQuery: Bool         // true for all

  static let get = HTTPMethodConfig(method: "GET", requiresBody: false, supportsQuery: true)
  static let post = HTTPMethodConfig(method: "POST", requiresBody: true, supportsQuery: true)
  static let put = HTTPMethodConfig(method: "PUT", requiresBody: true, supportsQuery: true)
  static let patch = HTTPMethodConfig(method: "PATCH", requiresBody: true, supportsQuery: true)
  static let delete = HTTPMethodConfig(method: "DELETE", requiresBody: false, supportsQuery: true)
}

/// Shared expansion logic for all HTTP method macros
protocol HTTPMacroExpansion {
  static var config: HTTPMethodConfig { get }
}

extension HTTPMacroExpansion {
  static func expansion(
    of node: AttributeSyntax,
    providingPeersOf declaration: some DeclSyntaxProtocol,
    in context: some MacroExpansionContext
  ) throws -> [DeclSyntax] {
    // 1. Validate function declaration
    guard let function = declaration.as(FunctionDeclSyntax.self) else {
      MacroHelpers.emitError(
        "@\(config.method) can only be applied to function declarations",
        node: node,
        context: context
      )
      return []
    }

    // 2. Validate async throws
    try MacroHelpers.validateAsyncThrows(function: function, context: context)

    // 3. Extract and validate path
    guard let path = ArgumentExtractors.extractPath(from: node, context: context) else {
      return []
    }
    try MacroHelpers.validatePathTemplate(path, context: context)

    // 4. Detect syntax style
    let usesOldSyntax = function.usesOldMacroSyntax()
    let newHeaders = function.detectHeadersMacro()
    let newBodyParam = config.requiresBody ? function.detectBodyMacro() : nil

    // 5. Check for syntax mixing
    if usesOldSyntax && (newBodyParam != nil || !newHeaders.isEmpty) {
      MacroHelpers.emitError(
        "Cannot mix old and new syntax for @\(config.method)",
        node: node,
        context: context
      )
      return []
    }

    // 6. Extract body parameter (if required)
    let bodyParam = try extractBodyIfRequired(
      node: node,
      function: function,
      newBodyParam: newBodyParam,
      context: context
    )

    // 7. Extract query parameters and headers
    let queryParams = ArgumentExtractors.extractQueryParameters(from: node, context: context)
    let headers = extractHeaders(node: node, newHeaders: newHeaders, context: context)

    // 8. Validate parameters exist in function signature
    let functionParams = MacroHelpers.extractParameterNames(from: function)
    try MacroHelpers.validatePathParameters(
      path: path,
      functionParameters: functionParams,
      context: context
    )
    if !queryParams.isEmpty {
      try MacroHelpers.validateQueryParameters(
        queryParams,
        functionParameters: functionParams,
        context: context
      )
    }

    // 9. Extract return type
    let returnType = MacroHelpers.extractReturnType(from: function) ?? "Void"

    // 10. Generate implementation
    return [generateImplementation(
      function: function,
      path: path,
      bodyParameter: bodyParam,
      queryParameters: queryParams,
      headers: headers,
      returnType: returnType
    )]
  }

  private static func extractBodyIfRequired(
    node: AttributeSyntax,
    function: FunctionDeclSyntax,
    newBodyParam: String?,
    context: some MacroExpansionContext
  ) throws -> String? {
    guard config.requiresBody else { return nil }

    if let newBody = newBodyParam {
      return newBody
    } else if let oldBody = ArgumentExtractors.extractBodyParameter(from: node, context: context) {
      return oldBody
    } else {
      MacroHelpers.emitError(
        "@\(config.method) requires a body parameter. Use @Body(\"paramName\") or body: argument",
        node: node,
        context: context
      )
      return nil
    }
  }

  private static func extractHeaders(
    node: AttributeSyntax,
    newHeaders: [(name: String, value: String, isParameter: Bool)],
    context: some MacroExpansionContext
  ) -> [(name: String, value: String, isParameter: Bool)] {
    if !newHeaders.isEmpty {
      return newHeaders
    } else {
      let oldHeaders = ArgumentExtractors.extractHeaders(from: node, context: context)
      return oldHeaders.map { (name: $0.key, value: $0.value, isParameter: false) }
    }
  }

  private static func generateImplementation(
    function: FunctionDeclSyntax,
    path: String,
    bodyParameter: String?,
    queryParameters: [String],
    headers: [(name: String, value: String, isParameter: Bool)],
    returnType: String
  ) -> DeclSyntax {
    let functionName = function.name.text
    let parameters = MacroHelpers.extractParameters(from: function)
    let paramList = parameters.map { "\($0.name): \($0.type)" }.joined(separator: ", ")

    // Generate path substitution
    let parser = PathTemplateParser(template: path)
    let pathCode = parser.generatePathSubstitution()

    // Generate additional request code
    var additionalCode = ""
    if let body = bodyParameter {
      additionalCode += generateBodyCode(body)
    }
    additionalCode += generateHeaderCode(headers)
    additionalCode += generateQueryParameterCode(queryParameters)

    // Check for interceptors
    let hasInterceptors = findParentProtocol(function)
      .map { InterceptorsMacro.hasInterceptors(from: $0) } ?? false

    // Use InterceptorCodeGenerator (already exists from Phase 10)
    return InterceptorCodeGenerator.generateMethodImplementation(
      functionName: functionName,
      parameters: paramList,
      returnType: returnType,
      pathCode: pathCode,
      method: config.method,
      additionalRequestCode: additionalCode,
      hasInterceptors: hasInterceptors
    )
  }

  private static func generateBodyCode(_ bodyParameter: String) -> String {
    "\n  request.setBody(try JSONEncoder().encode(\(bodyParameter)))" +
    "\n  request.addHeader(name: \"Content-Type\", value: \"application/json\")"
  }

  private static func generateHeaderCode(
    _ headers: [(name: String, value: String, isParameter: Bool)]
  ) -> String {
    guard !headers.isEmpty else { return "" }
    return headers.map { header in
      if header.isParameter {
        "\n  request.addHeader(name: \"\(header.name)\", value: \\(\(header.value)))"
      } else {
        "\n  request.addHeader(name: \"\(header.name)\", value: \"\(header.value)\")"
      }
    }.joined()
  }

  private static func generateQueryParameterCode(_ queryParameters: [String]) -> String {
    guard !queryParameters.isEmpty else { return "" }
    return queryParameters.map { param in
      "\n  request.addQueryParameter(name: \"\(param)\", value: \\(\(param)))"
    }.joined()
  }

  private static func findParentProtocol(_ function: FunctionDeclSyntax) -> ProtocolDeclSyntax? {
    var currentNode: Syntax? = Syntax(function)
    while let node = currentNode {
      if let protocolDecl = node.as(ProtocolDeclSyntax.self) {
        return protocolDecl
      }
      currentNode = node.parent
    }
    return nil
  }
}
```

**Usage (refactored GETMacro):**

### Pattern 2: Argument Extraction Helpers
**What:** Extract shared argument parsing logic into dedicated helper functions.
**When to use:** When multiple macros parse the same AttributeSyntax argument patterns.

**Example:**
```swift
// Sources/NetworkingMacros/Shared/ArgumentExtractors.swift
import SwiftSyntax
import SwiftSyntaxMacros

enum ArgumentExtractors {
  /// Extracts path from first macro argument (shared by all HTTP macros)
  static func extractPath(
    from node: AttributeSyntax,
    context: some MacroExpansionContext
  ) -> String? {
    guard let arguments = node.arguments?.as(LabeledExprListSyntax.self),
      let firstArg = arguments.first,
      let stringLiteral = firstArg.expression.as(StringLiteralExprSyntax.self),
      let segment = stringLiteral.segments.first?.as(StringSegmentSyntax.self)
    else {
      MacroHelpers.emitError("Macro requires a path argument", node: node, context: context)
      return nil
    }
    return segment.content.text
  }

  /// Extracts body parameter from macro arguments (POST/PUT/PATCH)
  static func extractBodyParameter(
    from node: AttributeSyntax,
    context: some MacroExpansionContext
  ) -> String? {
    guard let arguments = node.arguments?.as(LabeledExprListSyntax.self) else {
      return nil
    }

    for argument in arguments {
      if argument.label?.text == "body",
        let stringLiteral = argument.expression.as(StringLiteralExprSyntax.self),
        let segment = stringLiteral.segments.first?.as(StringSegmentSyntax.self)
      {
        return segment.content.text
      }
    }
    return nil
  }

  /// Extracts query parameters from macro arguments
  static func extractQueryParameters(
    from node: AttributeSyntax,
    context: some MacroExpansionContext
  ) -> [String] {
    guard let arguments = node.arguments?.as(LabeledExprListSyntax.self) else {
      return []
    }

    for argument in arguments {
      if argument.label?.text == "queryParameters",
        let arrayExpr = argument.expression.as(ArrayExprSyntax.self)
      {
        return arrayExpr.elements.compactMap { element in
          if let stringLiteral = element.expression.as(StringLiteralExprSyntax.self),
            let segment = stringLiteral.segments.first?.as(StringSegmentSyntax.self)
          {
            return segment.content.text
          }
          return nil
        }
      }
    }
    return []
  }

  /// Extracts headers from macro arguments (old syntax)
  static func extractHeaders(
    from node: AttributeSyntax,
    context: some MacroExpansionContext
  ) -> [String: String] {
    guard let arguments = node.arguments?.as(LabeledExprListSyntax.self) else {
      return [:]
    }

    for argument in arguments {
      if argument.label?.text == "headers",
        let dictExpr = argument.expression.as(DictionaryExprSyntax.self)
      {
        var headers: [String: String] = [:]

        for element in dictExpr.content.as(DictionaryElementListSyntax.self) ?? [] {
          if let keyString = element.key.as(StringLiteralExprSyntax.self),
            let keySegment = keyString.segments.first?.as(StringSegmentSyntax.self),
            let valueString = element.value.as(StringLiteralExprSyntax.self),
            let valueSegment = valueString.segments.first?.as(StringSegmentSyntax.self)
          {
            headers[keySegment.content.text] = valueSegment.content.text
          }
        }
        return headers
      }
    }
    return [:]
  }
}
```

### Pattern 3: Configuration-Driven Generation
**What:** Use data structures to encode per-method differences, allowing single generation pathway.
**When to use:** When variation is data (strings, bools) not behavior.

**Already implemented:** `HTTPMethodConfig` struct in Pattern 1 example.

**Impact:** Eliminates need for 5 separate `generateImplementation` functions that differ only by method name and body requirement check.

### Anti-Patterns to Avoid

- **Copy-paste inheritance simulation:** Do NOT create HTTPMacroBase struct with static methods expecting subclasses. Macros are structs with PeerMacro conformance, not class hierarchies.

- **String-based code generation after Phase 10:** InterceptorCodeGenerator already uses MacroTemplateKit Declaration ADT. Do NOT revert to string concatenation for DRY-extracted helpers.

- **Overgeneralization:** Do NOT try to merge configuration macros (Timeout, Cacheable, Measured) with HTTP macros. They serve different purposes and have different expansion signatures.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| SwiftSyntax AST construction | Manual `SyntaxFactory.make*` calls | MacroTemplateKit Declaration ADT | Phase 10 established this pattern; maintains consistency |
| Path parameter regex parsing | Custom regex with NSRegularExpression | PathTemplateParser.parse() | Already exists, tested, handles edge cases |
| Function signature validation | Custom async/throws detection | MacroHelpers.validateAsyncThrows() | Already exists, emits proper diagnostics |
| Diagnostic emission | Manual `context.diagnose()` calls | MacroHelpers.emitError() / emitWarning() | Consistent MessageID and severity handling |

**Key insight:** 80% of "new" code needed for DRY refactoring already exists in MacroHelpers.swift and PathTemplateParser.swift. The task is extraction and protocol composition, not reimplementation.

## Common Pitfalls

### Pitfall 1: Breaking Existing Test Contracts
**What goes wrong:** Refactoring shared logic changes expansion output, breaking 33 existing NetworkingMacros tests.

**Why it happens:** Subtle differences in error messages, whitespace, or ordering of generated statements cause macro expansion tests to fail even when functionality is identical.

**How to avoid:**
1. Run full test suite BEFORE refactoring: `swift test --package-path Packages/NetworkingMacros`
2. Refactor ONE macro at a time (start with smallest: DELETEMacro at 313 lines)
3. After each refactor, run: `swift test --filter DELETEMacroTests`
4. Use golden-master testing: compare AST structure, not string equality

**Warning signs:**
- Test failures in unrelated macros after refactoring one
- Diff shows only whitespace or newline changes
- Error message text differs but semantic meaning identical

### Pitfall 2: Protocol Static Method Dispatch Confusion
**What goes wrong:** Swift protocol static methods do not dispatch dynamically. Calling shared logic directly on `Self` fails.

**Why it happens:** Attempting to use protocol as base class (OOP thinking in protocol-oriented design).

**How to avoid:**
```swift
// ❌ WRONG: This will NOT work
public struct GETMacro: PeerMacro, HTTPMacroExpansion {
  public static func expansion(...) throws -> [DeclSyntax] {
    return Self.expansion(...)  // Infinite recursion!
  }
}

// ✅ CORRECT: Explicit protocol witness
public struct GETMacro: PeerMacro, HTTPMacroExpansion {
  public static let config = HTTPMethodConfig.get

  public static func expansion(...) throws -> [DeclSyntax] {
    return try (Self.self as HTTPMacroExpansion.Type).expansion(...)
  }
}
```

### Pitfall 3: Argument Extraction Order Dependency
**What goes wrong:** Extracting headers before detecting syntax style causes old-syntax detection to fail.

**Why it happens:** `usesOldMacroSyntax()` checks for `body:` and `headers:` labeled arguments. If you consume/remove these during extraction, detection returns false.

**How to avoid:**
1. ALWAYS detect syntax style BEFORE extracting arguments
2. Extraction should be read-only (don't mutate node)
3. Order in shared logic: validate → extract path → detect syntax → extract params

**Warning signs:**
- Deprecation warnings not appearing for old syntax
- Syntax mixing errors not triggered
- Test cases for old syntax failing after refactoring

### Pitfall 4: SwiftLint Complexity Budget Violations
**What goes wrong:** Extracting all logic into single protocol extension creates 150+ line function with cyclomatic complexity 20+.

**Why it happens:** All 5 macros combined have ~1500 lines; naive extraction into one place violates all lint budgets.

**How to avoid:**
- Split protocol extension across multiple private helper functions
- Keep main `expansion()` at <50 lines (orchestration only)
- Extract validators: `extractBodyIfRequired()`, `extractHeaders()`, etc.
- Use ArgumentExtractors enum for pure extraction logic (no context needed)

**SwiftLint exemption note:** NetworkingMacros already has file_length exemptions, but NOT cyclomatic_complexity. Stay under 15 complexity per function.

## Open Questions

1. **Should ArgumentExtractors be an enum or a struct with static methods?**
   - What we know: MacroHelpers is enum with static methods (established pattern)
   - What's unclear: Whether ArgumentExtractors warrants separate file vs. extension to MacroHelpers
   - Recommendation: Use enum in separate file for discoverability; likely to grow with Phase 11+ macros

2. **How to handle GET/DELETE edge cases where return type can be Void?**
   - What we know: DELETE normalizes nil/"Void" to "Void" (lines 251-256 in DELETEMacro.swift)
   - What's unclear: Whether GET should allow Void (currently requires explicit return type)
   - Recommendation: Shared logic should normalize returnType early; add optional `allowsVoidReturn` to HTTPMethodConfig

3. **Should old syntax deprecation warnings be escalated to errors?**
   - What we know: Currently emits warnings (all 5 macros), code still works
   - What's unclear: When to break backward compatibility
   - Recommendation: Keep warnings in 10.1; schedule error upgrade for Phase 12 (major version bump)
