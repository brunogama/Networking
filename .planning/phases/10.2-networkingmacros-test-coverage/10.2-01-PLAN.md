<technical_notes>
## MacroTesting Framework Usage

The pointfree MacroTesting framework provides:
- `withMacroTesting(macros:record:operation:)` - Configure test environment
- `assertMacro { source } expansion: { expected }` - Validate expansion
- `assertMacro { source } diagnostics: { expected }` - Validate error messages
- Recording mode to auto-generate expected output

### Key Differences from SwiftSyntaxMacrosTestSupport

| Feature | SwiftSyntaxMacrosTestSupport | MacroTesting |
|---------|------------------------------|--------------|
| Configuration | Per-assertion macros dict | withMacroTesting scope |
| Syntax | assertMacroExpansion() | assertMacro { } expansion: { } |
| Recording | Manual | Automatic with record mode |
| XCTest/Swift Testing | XCTest only | Both supported |

### Why HTTPPhantomTypeTests Works

HTTPPhantomTypeTests.swift successfully uses `@testable import NetworkingMacrosPlugin` because:
- It tests utility types (HTTPMethod, TypedHTTPTemplate)
- These types don't require macro expansion runtime
- They're regular Swift types defined in the macro module

The challenge with macro expansion tests:
- Macro types (GETMacro.self) conform to Macro protocol
- SwiftSyntaxMacros provides Macro protocol
- MacroTesting handles expansion via SwiftSyntax directly

### Expected GETMacro Expansion

Based on HTTPMacroExpansion protocol implementation, @GET should generate:
- Function signature (original)
- Implementation function with HTTP request building
- Path parameter interpolation
- Query parameter handling
- Response decoding

The exact output depends on the macro arguments and function signature.
</technical_notes>
