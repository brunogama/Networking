## Technical Notes

### MacroTesting Framework Usage

**Key API Patterns**:
```swift
// Test class configuration
override func invokeTest() {
  withMacroTesting(macros: [GETMacro.self]) {
    super.invokeTest()
  }
}

// Expansion assertion
func testExample() {
  assertMacro {
    """
    @GET("/path")
    func method() async throws -> Type
    """
  } expansion: {
    """
    // Expected expanded code
    """
  }
}

// Diagnostic assertion
func testError() {
  assertMacro {
    """
    @GET
    func method() -> Type
    """
  } diagnostics: {
    """
    @GET
    ┬───
    ╰─ 🛑 Error message
    """
  }
}
```

### Macro Expansion Output Format

The HTTPMacroExpansion protocol generates:
1. **Path binding**: `let path = "/users/\(id)"`
2. **Request initialization**: `var request = HTTPRequest(method nil .GET, path path, baseURL baseURL)`
3. **Execute call**: `let response = client.execute(request)`
4. **Decode return**: `return JSONDecoder().decode(Type.self, from response.data)`

Note: The expansion output format includes Swift syntax oddities:
- `method nil .GET` (label-less syntax)
- `path path` (label-less argument syntax)
- `from response.data` (labeled argument)

These are valid SwiftSyntax representations of the generated code.

### Record Mode Workflow

1. Set `record: .all` in `withMacroTesting`
2. Run tests (they fail with "Automatically recorded" message)
3. MacroTesting writes expansion output to test file
4. Remove `record: .all` parameter
5. Re-run tests (they pass against recorded snapshots)

This ensures expected output matches actual macro expansion exactly.
