## Key Decisions

### Decision 1: Use MacroTesting Record Mode
- **Context**: Manual expectation writing is time-consuming and error-prone
- **Decision**: Use `withMacroTesting(record: .missing)` to capture actual expansions
- **Rationale**: MacroTesting automatically records first run, verifies subsequent runs
- **Impact**: Reduced test authoring time from hours to minutes, improved accuracy
- **Files affected**: All test files in Phase 10.2.1

### Decision 2: Defer @Headers Closure Syntax Tests
- **Context**: @Headers macro uses `@HeaderBuilder` result builder closure syntax
- **Decision**: Implement 2 diagnostic tests, defer closure syntax expansion tests
- **Rationale**: MacroTesting limitations with result builder trailing closures
- **Mitigation**: APIMacroTests provides full integration test coverage
- **Impact**: 2/7 planned tests implemented, full behavior validated via integration tests
- **Files affected**: HeaderBuilderTests.swift

### Decision 3: Fix HeadersMacro Error Handling
- **Context**: HeadersMacro was throwing errors instead of emitting diagnostics
- **Decision**: Replace `throw MacroExpansionError` with `MacroHelpers.emitError` + `return []`
- **Rationale**: Marker macros (PeerMacro/MemberMacro) should emit diagnostics, not throw
- **Impact**: Cleaner diagnostic messages, aligns with InterceptorsMacro pattern
- **Files affected**: HeadersMacro.swift
- **Classification**: Bug fix (Rule 1)
