## Lessons Learned

1. **MacroTesting framework limitations**: Result builder trailing closures require special handling that MacroTesting doesn't fully support yet. Integration tests provide better coverage for complex macro interactions.

2. **Marker macro error pattern**: Macros that validate syntax but don't generate code (PeerMacro/MemberMacro) should use `MacroHelpers.emitError` + `return []` instead of throwing errors for cleaner diagnostic messages.

3. **Separation of test concerns**: Testing macro syntax validation separately from code generation integration provides clearer test organization and better diagnostic coverage.
