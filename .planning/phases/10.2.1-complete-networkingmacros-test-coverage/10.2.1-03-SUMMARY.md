## Key Learnings

### MacroTesting Record Mode Best Practice
Using `withMacroTesting(record: .missing, macros: [...])` is far more efficient than manually writing expected expansions:

1. **First run**: MacroTesting records actual expansion output automatically
2. **Second run**: Tests verify against recorded snapshots
3. **Changes**: Re-record by deleting snapshot or using `record: .all`

This workflow reduces manual expectation writing from hours to minutes.

### @POST/@PUT Require @Body Annotation
The HTTP macros validate that @POST/@PUT methods have a @Body parameter:
- Without @Body: Emits diagnostic "🛑 @POST requires a body parameter. Use @Body("paramName") macro."
- With @Body: Expands successfully with `request.body = JSONEncoder().encode(user)`

This compile-time validation prevents runtime errors from missing request bodies.

### @Cacheable is a PeerMacro
Unlike @DefaultHeaders/@Timeout (which APIMacro reads to add properties), @Cacheable:
- Generates a separate extension with static `cacheConfiguration` property
- Returns `CacheConfiguration(duration: .ttl(300), policy: .standard)`
- Can be applied to protocols (not individual methods)

### Interceptor Order Preservation
@Interceptors([...]) array order is preserved in generated code:
```swift
@Interceptors([AuthInterceptor(), LoggingInterceptor(), RetryInterceptor()])
// Generates:
self.interceptors = InterceptorChain(
  requestInterceptors: [AuthInterceptor(), LoggingInterceptor(), RetryInterceptor()],
  responseInterceptors: [AuthInterceptor(), LoggingInterceptor(), RetryInterceptor()]
)
```

Both request and response interceptors use the same array (bidirectional).
